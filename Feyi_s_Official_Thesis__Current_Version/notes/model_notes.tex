Other strands of CEP research reinforce this gap. Bayesian-network extensions \cite{wasserkrug2010efficient, wasserkrug2012model} estimate probabilities for observed or derived events but require the presence of an event instance to initiate propagation. Interval-based approaches to temporal uncertainty \cite{zhang2013recognizing} reinterpret event timestamps but always presume the existence of the event whose timestamp is being constrained. Methods grounded in lineage tracking and probabilistic NFAs \cite{shen2008probabilistic, kawashima2010complex, chuanfei2010complex, wang2013complex} compute confidence values for complex event patterns over stochastic input streams, yet their evaluation mechanisms remain inactive when the stream falls silent. Likewise, frameworks such as CEP2U \cite{cugola2015introducing} and uncertainty-aware extensions of Esper and Flink \cite{moreno2019managing} account for uncertainty in measurements and rule firing while offering no semantics for absent events. Across this body of work, progression only occurs when new inputs are delivered; in the presence of temporary data gaps, processing halts, and no provision is made for preserving the continuity of computation.

A small number of IoT-oriented studies acknowledge the impact of missing events on event-driven analytics and attempt to address the issue through external data-level reconstruction or synthetic event generation. For example, \citet{gkoulis2025assessing} evaluate ``event fabrication'' methods—such as naive interpolation and exponential smoothing—for filling gaps in sensor data to support real-time IoT applications. Similarly, \citet{gkoulis2024hybrid} incorporate an event-generation mechanism into a quality-aware CEP platform to compensate for missing sensor updates, characterizing the resulting complex events using completeness and timeliness metrics. While these approaches demonstrate the practical need to preserve continuity in IoT event streams, both treat gap-filling as a preprocessing or augmentation step applied \emph{before} or \emph{outside} of the CEP semantics. The event processor remains unaware that an expected observation failed to materialize, cannot distinguish fabricated from genuine inputs, and does not propagate uncertainty associated with the generated values. As a result, these methods do not provide an architectural mechanism for integrating reconstruction with high-level reasoning or maintaining internal-state continuity during data gaps.

\section{Uncertainty and Missing Data in Complex Event Processing}
Event-driven systems commonly address data quality challenges through uncertainty-aware extensions to CEP. A substantial body of work has examined how uncertainty in event data can be represented and propagated during pattern evaluation. Bayesian-network–based approaches estimate probabilities for observed or derived events by propagating likelihoods through inference structures \citep{wasserkrug2010efficient, wasserkrug2012model}, while interval-based temporal models reinterpret event timestamps as ranges to accommodate imprecise ordering \citep{zhang2013recognizing}. Probabilistic CEP engines based on lineage tracking and automata-based evaluation extend this perspective by maintaining probability distributions over complex event patterns as events arrive \citep{shen2008probabilistic, kawashima2010complex, chuanfei2010complex, wang2013complex}. Similarly, frameworks such as CEP2U \citep{cugola2015introducing} and uncertainty-aware extensions of Esper and Flink \citep{moreno2019managing} incorporate uncertainty in measurements and rule inference into existing CEP engines.

Across this literature, uncertainty is primarily treated as a property of event values or inference mechanisms, with a focus on noise, imprecision, and probabilistic reasoning. The progression of event-driven computation, however, remains fundamentally tied to the arrival of input events, and existing CEP engines provide limited support when expected observations do not arrive. Survey work highlights that missing data is a common challenge in real-world event streams and that gaps in input data can undermine the effectiveness of complex event processing, particularly in large-scale and high-velocity environments \citep{tawsif2018review}. Unlike noisy or imprecise observations, missing data corresponds to the absence of expected information, which disrupts the progression of event-driven computation.

Recent work has begun to address this limitation through compensation mechanisms. \citet{gkoulis2025assessing} evaluate event-fabrication techniques such as interpolation and smoothing to replace missing sensor updates in real-time IoT applications, while related work integrates event generation into quality-aware CEP pipelines and assesses the impact of fabricated events using completeness and timeliness metrics \citep{gkoulis2024hybrid}. \citet{vijayakumar2009missing} adopts a prediction-based approach, integrating Kalman-filter–based estimation into SQL-based CEP engines as a query operator to allow computation to continue during short-term interruptions. Structural recovery approaches instead operate after execution, using Petri-net process models to complete incomplete event sequences \citep{wang2013efficient}.

Overall, existing approaches address missing data by replacing missing events, without explicitly exposing the uncertainty introduced by reconstruction during event processing. As a result, downstream event logic cannot assess how inference affects the correctness of CEP results. This limitation motivates the need for a model that detects missing observations at runtime, reconstructs them as events with explicit confidence, and supports both continuity and correctness during event-driven processing.
