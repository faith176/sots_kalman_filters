\chapter{Foundations of Event-Driven Operation with Missing Observations}\label{ch:semantics}

The literature review in \chref{ch:literature-review} identifies a reliability gap in SoTS: while system behaviour depends on continuous streams of observational events, existing approaches provide limited support for maintaining correct and continuous operation when such streams are temporarily disrupted.
Addressing this gap requires an explicit model of system operation that captures how events are generated, when they are expected to occur, and how system state may be inferred when expected events do not arrive.
This chapter presents an abstract model for event-driven systems that enables confidence-aware processing under missing or delayed observations. This model provides the basis for the system architecture introduced in \chref{ch:architecture}.

\paragraph{Model Scope and Assumptions}
This chapter models events and temporary observation unavailability in event-driven systems. All system inputs are assumed to be discrete, timestamped events.
Each event generator is assumed to expose a known expected interval $\Delta_g$, enabling the detection of missing observations through event time and tolerance windows. Missing observations are assumed to be short-duration interruptions rather than long-term outages, justifying the use of short-term prediction in place of observation.
Reconstruction mechanisms are data-agnostic and require only numerical event values suitable for short-term prediction. Predictors are assumed to expose information about the uncertainty of their estimates over the reconstruction time range.
The treatment of late events is limited to classification. Retroactive correction, reconciliation under delayed observations, and reordering across multiple event streams are excluded from the model and left for future work (\chref{ch:conclusion}).



\section{Event Model and Stream Semantics}
\label{sec:events-streams}

An \emph{event} represents an observation about an underlying system or process being monitored and is defined as
\begin{equation}
e = \langle id, type, src, t, v, m \rangle ,
\end{equation}
\noindent
where $id$ uniquely identifies the event, $type$ represents the class of the event, $src$ identifies the source of the event, $t$ is the event time indicating when the observed phenomenon occurred, $v$ is the observed or inferred value, and $m$ represents metadata.

An \emph{event stream} $E$ is a sequence of events, where each event $e \in E$ is associated with an event time $t(e)$.
\begin{equation}
E = \langle e_1, e_2, \dots \rangle .
\end{equation}

Events originate from a set of \emph{event generators} $\mathcal{G}$. Each generator produces events at a specified expected sampling interval $\Delta_g$.
\begin{equation}
g = \langle id_g, type_g, \Delta_g \rangle
\end{equation}
\noindent
where $id_g$ uniquely identifies the event generator. For each event $e$ produced by generator $g$, the source attribute is set to $e.src = id_g$ and the type attribute is set to $e.type = type_g$.

Events produced by generators are made available to downstream components through the event stream $E$. \emph{Event consumers} form a set $\mathcal{C}$, where each consumer $c \in \mathcal{C}$ observes and reacts to events from the event stream $E$.



\section{Scheduling and Missing Observations}
\label{sec:scheduling-missing} % Who acts
According to \citet{wasserkrug2006taxonomy}, event streams are subject to occurrence uncertainty originating at their sources, such that observed event streams may represent only partial views of the underlying system behaviour. In event-driven systems, this uncertainty must be resolved at runtime to determine whether an expected observation has occurred or whether its absence should be interpreted as a delay or missingness.

Let $\kappa$ represent a coordinating component that observes the event stream $E$ and has access to the expected sampling intervals $\Delta_g$ of event
generators $g \in \mathcal{G}$. Using the current system time $t_{\mathrm{now}}$, $\kappa$ compares expected event times with the appearance of events in the event stream to classify the status of expected observations.

For each generator $g \in \mathcal{G}$, let $t^{\mathrm{last}}_g$ represent the event time of the most recent event in $E$ produced by $g$ that has been accounted for
by $\kappa$. The next expected event time for generator $g$ is defined as
\begin{equation}
t^{\mathrm{exp}}_g = t^{\mathrm{last}}_g + \Delta_g .
\end{equation}
A tolerance window $\varepsilon_g$ is associated with generator $g$ and defines the acceptable deviation from the expected event time.


Each expected observation is classified according to the set
\begin{equation}
\mathcal{S} = \{\textsc{Observed}, \textsc{Late}, \textsc{Missing}\}.
\end{equation}

An expected observation for generator $g$ at time $t^{\mathrm{exp}}_g$ is classified as:
\begin{itemize}
    \item \textsc{Observed} if there exists an event $e \in E$ such that
    $e.src = id_g$, $e.type = type_g$, and
    $\lvert e.t - t^{\mathrm{exp}}_g \rvert \le \varepsilon_g$.

    \item \textsc{Late} if there exists an event $e \in E$ such that
    $e.src = id_g$, $e.type = type_g$, and
    $\lvert e.t - t^{\mathrm{exp}}_g \rvert > \varepsilon_g$.

    \item \textsc{Missing} if $t_{\mathrm{now}} >
    t^{\mathrm{exp}}_g + \varepsilon_g$ and no such event has been observed.
\end{itemize}
\noindent
Once an expected observation is classified as \textsc{Missing}, the model does not retroactively revise this classification upon later event arrival. Classification
reflects the information available at the time of evaluation.


\section{State-Based Prediction and Confidence}
\label{sec:state-based-inference} % How its done

For each generator $g \in \mathcal{G}$, a state-based predictor is associated with $g$ and maintains an internal state $x_g$. The predictor is invoked by $\kappa$ to advance its state using observed events and to perform prediction when an expected observation is classified as \textsc{Missing}.

The predictor provides two operations:
\begin{align}
\mathcal{U}_g\bigl(x_g^{s-1}, e_g^{s}\bigr)
&\quad\text{(update)}, \\
\hat{v}_g^{s} = \mathcal{P}_g\bigl(x_g^{s-1}\bigr)
&\quad\text{(prediction)}.
\end{align}

Each index $s$ corresponds to a successive expected observation for generator $g$. At each step, exactly one operation is applied based on the classification of the expected observation. If the status is \textsc{Observed}, the update operation $\mathcal{U}_g$ incorporates the event and advances the internal state from $x_g^{s-1}$ to $x_g^{s}$. If the status is \textsc{Missing}, the prediction operation $\mathcal{P}_g$ produces an estimate $\hat{v}_g^{s}$ from the previous state and advances the state in the absence of an observation. 
% This separation follows standard formulations of state-based estimation \cite{simon2006optimal}.

Uncertainty associated with prediction is represented through a confidence value derived from the predictor state. A confidence function is defined as
\begin{equation}
conf_g^{s} = \mathcal{C}\bigl(x_g^{s}\bigr).
\end{equation}
When prediction is applied, the confidence value reflects the uncertainty encoded in the updated predictor state. When an event is observed directly, the corresponding confidence may be assigned its maximum value.

% Representing uncertainty as event metadata follows requirements identified in prior work on uncertainty in event-driven processing \cite{cugola2015complex}.


\section{Stream Augmentation}
\label{sec:confidence-stream-augmentation}

When an expected observation is classified as \textsc{Missing}, the predictor produces an estimated value that is materialized as a derived event and inserted into the event stream. This allows downstream components to continue operating over a temporally complete, partially inferred event sequence.

For each expected observation associated with generator $g$, a derived event is constructed as
\begin{equation}
\hat{e}_g =
\langle id, type_g, id_g, t^{\mathrm{exp}}_g, \hat{v}_g, m_{\mathrm{pred}} \rangle ,
\end{equation}
\noindent
where $\hat{v}_g$ represents the predicted value, and $m_{\mathrm{pred}}$ records metadata indicating that the event was derived rather than directly observed, including the confidence value $conf_g^{s}$ produced by the predictor.

When an expected observation is classified as \textsc{Observed}, the corresponding observed event may be augmented with confidence metadata. In both cases, observed and derived events share the same structural representation and differ only in their metadata.

Derived events are inserted into the event stream to form an augmented stream
\begin{equation}
E^{+} = E \cup \{ \hat{e}_g \},
\end{equation} 
which provides a temporally complete view of system behaviour. Downstream event consumers may distinguish observed and derived events through metadata, while processing them uniformly with respect to event time and type.

\section{Confidence-Aware Event Processing}
\label{sec:confidence-aware-semantics}
The augmented event stream $E^{+}$ produced by the model is intended to be consumed by downstream event-driven processing components, such as CEP engines. Let $e$ represent an event in $E^{+}$ with an associated confidence value $conf(e) \in [0,1]$ encoded in its metadata. Event patterns and temporal relations may incorporate confidence values through additional predicates or aggregation functions.

For example, a confidence-aware condition may require
\begin{equation}
conf(e) \ge \theta ,
\end{equation}
\noindent
where $\theta$ is a confidence threshold. Aggregate confidence over a set of events may also be computed using functions such as minimum, maximum, average, or most recent confidence. These mechanisms allow uncertainty introduced by derived events to be accounted for explicitly, while preserving the structural and temporal semantics of event-driven processing.

\section{Reliability Semantics under Missing Observations}
\label{sec:reliability-semantics}

The event model defined in this chapter provides a semantic foundation for
reliable operation in event-driven systems under temporary observation
unavailability. In this context, reliability is understood as the ability of the
system to continue producing semantically meaningful outputs despite missing
inputs, while explicitly characterizing the uncertainty introduced by inference.

By classifying expected observations at runtime and materializing derived events
in place of missing observations, the model preserves the temporal continuity of
the event stream. This ensures that downstream event-driven processing can
proceed without suspension, maintaining continuity of service even when
observations are temporarily unavailable.

Correctness is addressed by distinguishing observed and derived events through
metadata and by attaching confidence values that reflect the uncertainty of
predicted observations. As a result, the model does not conceal data absence, but
makes it explicit and measurable, allowing downstream components to reason about
uncertainty without altering event-time semantics.

Taken together, these properties support reliable event-driven operation by
preserving temporal structure, enabling continued processing, and making the
effects of missing data explicit rather than implicit. The model therefore
addresses the reliability gap identified in the literature by providing semantic
mechanisms for operating under incomplete observation.
